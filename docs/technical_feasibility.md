# Техническая осуществимость и ограничения

Статус: предварительное предложение по результатам аудита 2026-10-28. Это не гарантия совместимости или юридическое заключение.

## Уточнение целевого интерфейса (2026-10-29)

Пользователь хочет, чтобы визуальная панель по возможности выглядела частью Dota и работала только при активном Skin Cat. Это продуктовая цель, а не вывод о доступности конкретной техники. Сейчас реализовано отдельное top-level OS-окно; оно не запускается без Skin Cat, скрывается при его уходе в трей и центрируется на выбранном экране.

Внутрипроцессное отображение разрешено исследовать как отдельный вариант, но до design review остаётся `BLOCKED`. Review должен назвать конкретный интерфейс интеграции, проверить поддержку Windows/Linux/Wayland, влияние на процесс и совместимость с защитой игры. Запрет обхода античита/защиты, чтения закрытого состояния, автоматизации ввода и модификации игрового сервера/сети остаётся неизменным. Не заявлять безопасную работу или отсутствие игрового преимущества только на основании визуального намерения.

Для статистики допустимо рассматривать только исторические данные публичных профилей по разрешённым API с уважением privacy opt-out. Открытая история сама по себе не делает live-профилирование соперников нейтральным; получение roster из текущего матча и отображение боевых рекомендаций требуют отдельной оценки.

## Реализуемо в первой версии

- PySide6/Qt Widgets, локальная навигация, QSS, формы, поиск и model/view — штатный путь для общего Python GUI-кода.
- Runtime-зависимость закреплена на `PySide6-Essentials`, в котором есть QtCore/QtGui/QtWidgets, чтобы в первой версии не ставить неиспользуемые Addons и WebEngine. Этот набор поддерживает нужные виджеты; wheel packaging и smoke test остаются обязательными перед выпуском.
- SQLite, миграции, локальные профили и JSON import/export не требуют работающей игры или сети.
- Обнаружение Steam можно сделать read-only: искать конфигурации пользователя и каталоги библиотек на Windows/Linux, поддерживать ручной путь и не запускать Steam.
- Переключение языка на Qt можно построить на Qt Linguist TS/QM и QTranslator. Документация Qt описывает workflow `lupdate` → `.ts` → `lrelease` → `.qm` [F-04].
- Плавающую companion-панель можно реализовать как обычное Qt Tool window с флагом always-on-top. Она не читает процесс игры и не изменяет её; отображение поверх эксклюзивного полноэкранного режима зависит от ОС/композитора и не гарантируется.
- Локальные обще-доступные статистические обзоры технически возможны через публичные API, но только после выбора поставщика, проверки лицензии/terms, ограничений, приватности, свежести и методики [F-02, F-03].

## Основные риски и пробелы

1. **Права на игровые данные и медиа.** Метаданные и изображения — разные категории. Не включать изображения/модели/звуки игры в репозиторий или сборки без подтверждённой лицензии и правил распространения.
2. **Неопределённость интеграции с игрой.** Официальная справка Steam предупреждает о сторонних модификациях файлов/текстур; Subscriber Agreement ограничивает несанкционированные моды и вмешательство [F-05]. Долгосрочное направление — оценить локальную косметическую настройку на устройстве пользователя, но это не подтверждает разрешённость или VAC-safety. Writer имеет статус `BLOCKED` до отдельного review правил, совместимости, отката и backup/restore; начальные этапы остаются read-only.
3. **Приватность и честная игра.** Разрешены только открытые публичные агрегаты с понятной provenance. Нельзя выводить информацию, закрытую настройками игрока, или данные, доступные только через чтение процесса/сетевой обход.
4. **Статистика игроков в overlay.** Публичные метрики участников матча могут давать преимущество даже без скрытых данных. В Steam Agreement есть широкое правило о software, способном дать unfair advantage, поэтому конкретное использование такой панели в live-матче требует отдельного review; допустимость и VAC-safety не обещаются [F-05]. До решения показывать только вручную выбранные публичные профили и исторические метрики; без состава из процесса игры, обхода privacy и персональных live-рекомендаций.
5. **API и лимиты изменяются.** OpenDota публикует player endpoints и лимиты; условия и квоты нужно перепроверять перед подключением и документировать в приложении [F-02]. Offline-first — обязательное поведение.
6. **Steam path layouts разнообразны.** Несколько библиотек, symlink, регистр имён, внешние диски и Proton требуют фикстур и ручного override. Универсальное автообнаружение нельзя обещать до тестов.
7. **Windows packaging/runtime.** PySide6 несёт Qt runtime/plugins; standalone пакет увеличивает размер, требует smoke test на чистой Windows и проверки лицензий/notice. В локальном окружении Windows нет.
8. **Linux packaging.** AppImage может иметь проблемы с platform plugins, системными библиотеками, Wayland/X11 и разных дистрибутивах. Выбор AppImage или альтернативы следует сделать после прототипа и чистого теста, не заранее.
9. **Python 3.14.** Текущая локальная пара Python 3.14.7/PySide6 6.12.0 установлена. Это подтверждает наличие пакетов в данном окружении, но не подтверждает поддерживаемый базовый диапазон и Windows packaging. Предлагается зафиксировать базовый Python 3.12 для CI и отдельно проверять 3.14 на Linux до официального расширения матрицы.
10. **Локализация.** TS/QM обеспечивают каталогизацию, но полнота зависит от дисциплины в строках UI и валидации в CI. Нужны критические UI-ключи, Cyrillic/Unicode paths, plural forms и проверка каталогов обеих локалей.
11. **Производительность.** До baseline нужно измерить cold/warm startup, idle CPU, RSS, поиск и базовые SQLite-запросы. До измерения не ставить оптимизационные обещания. Использовать Qt model/view, индексы и отложенную загрузку.

## Ручная замена локального VPK (2026-10-31)

**Статус: экспериментальная функция реализована; проверена только на временных тестовых VPK.**

Skin Cat предоставляет ручную операцию для файла, который пользователь получил самостоятельно: выбрать папку Dota 2, исходный `.vpk` и конкретный игровой `.vpk`, подтвердить замену; приложение создаёт резервную копию вне папки игры. Восстановление доступно из интерфейса и проверяет хеш резервной и текущей версии, чтобы не перезаписывать внешние изменения. Операции выполняются в рабочем потоке и требуют закрытой Dota 2. Приложение не загружает, не каталогизирует, не кеширует и не распространяет VPK.

Проверки на временных каталогах не подтверждают совместимость с конкретной сборкой Dota 2, Steam verify/update, правилами Valve или VAC. Не утверждать, что мод будет виден другим игрокам или безопасен для сетевой игры. Права на конкретный файл и содержащиеся в нём сторонние/Valve-активы остаются ответственностью пользователя; лицензия сайта или кода не считается лицензией на каждый VPK. Условия и границы источника зафиксированы в [F-15](source_registry.md).

Ограничения текущей реализации: Linux-first; Windows и Proton не проверены end-to-end. Реальную установку игры не изменяли. Не выполнять сетевую загрузку, массовое применение, работу при запущенной игре, обход защиты/античита, модификацию процесса, памяти, ввода, сети или серверного состояния. При ручной проверке сначала использовать тестовую копию игры и убедиться, что восстановление работает.

## Первая целевая платформа

Первая поставляемая версия ориентирована на Linux. Windows остаётся платформой будущей совместимости и CI, но не блокирует Linux-first выпуск. Локальная проверка доступна на Linux/Python 3.14; до объявления поддерживаемого первого выпуска нужно дополнительно определить фактическую среду пользователя и проверить запуск и выбранный формат пакета на ней. На текущем этапе готовность wheel не равна готовности нативного установщика или подтверждённой интеграции с игровыми файлами.

## Подход к безопасности данных

- Импорт JSON: строгая схема, неизвестные поля по явной политике, лимиты размера/длины/числа сущностей, уникальность ID, корректные ссылки.
- Пути: хранить ссылки/относительные метаданные, запрещать traversal, проверять канонический путь и symlink, не доверять путям из import.
- Восстановление: preview, явное подтверждение, временная запись и атомарная замена приложения-owned файлов.
- SQLite: foreign keys, транзакции, схема миграций и периодический `PRAGMA integrity_check`.
- Сеть: отключена до запроса пользователя; общие timeout/size limit, HTTP ошибки без блокировки интерфейса, ограниченный cache.
- Журналы: redaction ключей/секретов; приложение не просит Steam пароль, cookie или API credentials в Milestone 1.
- Нет требований administrator/root и нет молчаливого удаления/перезаписи.

## Предлагаемые измерения и пороги

На первом Linux baseline и затем Windows CI/clean VM записывать версии ОС/Python/Qt, размер каталога данных и конфигурацию машины.

| Метрика | Как замерить | Предварительный порог для review |
|---|---|---|
| Холодный старт до интерактивного окна | внешний monotonic timer, 5 прогонов, медиана | ≤ 2.5 s на зафиксированной reference-машине |
| Прогретый старт | 5 прогонов, медиана | ≤ 1.5 s на reference-машине |
| Idle CPU через 60 s | process CPU time за 60 s | < 1% одного логического ядра в среднем |
| RSS после открытия sample catalog | ОС-процесс, каталог из 10k записей | ≤ 250 MiB как provisional target |
| Поиск по 10k sample records | медиана/95p 20 прогонов | ≤ 100 ms / ≤ 200 ms |
| SQLite простой запрос | 1000 профилей/10k записей, медиана/95p | ≤ 20 ms / ≤ 50 ms |
| Импорт/экспорт профиля | профиль 1 MiB, валидировать и round-trip | ≤ 1 s на reference-машине |

Это стартовые цели, не результаты измерений. Зафиксировать команду/скрипт, конфигурацию, raw samples и перцентиль; корректировать targets по baseline до объявления регрессионных gates.
