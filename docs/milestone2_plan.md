# План Milestone 2 — каталог и локальная подборка

Статус: каталог и единая локальная подборка показаны в оверлее; Linux-проверки пройдены. Реальные данные предметов и Windows CI ещё не подтверждены. Именованные профили исключены из продукта; старые записи сохраняются в legacy-таблицах. Реальная интеграция, меняющая игру или аккаунт, в этап не входит.

## Реализовано

- Резервная копия SQLite базы приложения в ZIP с manifest/SHA-256; предварительная проверка и просмотр состава перед восстановлением; Steam/Dota файлы не включаются.
- Схема SQLite v3 хранит демонстрационный каталог, избранное, legacy-наборы и новую единую подборку с внешними ключами.
- В UI есть демонстрационные записи по 11 категориям, поиск, фильтры категории/героя/слота и избранное.
- В оверлее одна локальная подборка: каталог и выбранные записи разделены вкладками; можно добавить и удалить запись без именованных профилей.
- Миграция схемы v3 переносит косметику единственного старого профиля в новую подборку; если старых профилей несколько, оставляет их нетронутыми и не делает неоднозначное слияние.
- RU/EN строки добавлены для каталога, единой подборки и экрана ожидания. В базу не включались игровые изображения, звуки или извлечённые файлы.

## Цель

Дать пользователю единый каталог экипируемых категорий Dota 2 и одну локальную подборку косметики. Подборка не означает, что предмет принадлежит пользователю или применён в матче.

Долгосрочное направление проекта — изучить безопасный локальный workflow визуальной настройки. Milestone 2 его не реализует: нужен отдельный дизайн и проверка правил, совместимости, обратимости и безопасного восстановления.

## Объём

1. Ввести типизированные метаданные каталога: герой, предмет, категория, слот, совместимость, источник, версия данных и лицензия медиа.
2. Поддержать категории героев и их слотов, курьеров, вардов, announcer/killstreak, музыкальных наборов, погоды, ландшафта, HUD, экранов загрузки, насмешек и другие категории по мере подтверждения источников.
3. Добавить поиск, фильтры, избранное и страницу подробностей без загрузки всего каталога в UI.
4. Поддерживать одну подборку выбранных каталожных записей без создания/копирования/переименования именованных профилей.
5. Показывать явные образцы для демонстрационных данных; не включать игровые изображения, модели, звуки или извлечённые файлы без лицензии.
6. Добавить локальную справочную запись/макет тира значка героя, если это нужно пользователю. Она не меняет официальный Dota Plus уровень, опыт, награды и видимость в игре.

## Не входит

- Запись или подмена игровых ресурсов, аккаунтного инвентаря, hero level/tier или владения предметами.
- Внедрение кода в игру, чтение памяти, обход античита, скрытых данных или ограничений доступа.
- Заявление, что локальная подборка видна в игре или другим игрокам.

Будущий локальный writer может рассматриваться только как отдельный этап после review. Он не должен менять серверное владение/прогресс, требовать обхода защиты или заявляться как VAC-safe без подтверждения.

## Последовательность реализации

1. Согласовать схему модели и список метаданных источников; добавить миграцию SQLite и тестовые fixture без игровых ассетов.
2. Реализовать сервис каталога и проверку связей «герой — предмет — слот — тип».
3. Добавить каталог в UI с поиском, фильтрами, пустыми состояниями и RU/EN строками.
4. Сохранить каталог и единую подборку; named-profile CRUD/import/export исключены из пользовательского приложения.
5. Добавить локальный макет тира героя с постоянной маркировкой «только в приложении» либо оставить только справочную информацию, если UI создаёт ложное впечатление игрового прогресса.
6. Пройти тесты миграций, валидации, импорта, локализации и проверку, что Steam/Dota каталоги не открываются на запись.

## Приёмка

- Каждая запись содержит стабильный ID, тип, совместимость, provenance и состояние лицензии.
- Категории и неизвестные типы отображаются без потери данных.
- Единая подборка полностью доступна offline и не требует Steam-входа.
- Миграции не удаляют старые пользовательские profile rows.
- Интерфейс ясно различает локальную подборку/макет и фактический игровой инвентарь/прогресс.
- Все новые пользовательские строки присутствуют на русском и английском.

После этого отдельным этапом можно оценивать публичные аналитические источники и оверлей статистики. Для live-матча остаётся обязательной отдельная проверка политики; автоматическое чтение состава матча не входит в этот этап.

## Overlay-first направление (следующий UX этап)

Целевой интерфейс — минимальное окно с логотипом Skin Cat и статусом ожидания Dota 2 плюс компактная полупрозрачная иконка, раскрывающая панель с вкладками `Статистика`, `Косметика`, `Герой`. В косметике действует одна локальная подборка без именованных профилей. Настройки языка открываются из главного окна.

Первый прототип — отдельное top-level OS окно без внедрения в игру: после обнаружения процесса Dota 2 появляется компактная кнопка, нажатие раскрывает панель с вкладками `Статистика`, `Косметика`, `Герой`; вкладка статистики открывается первой. До запуска игры главное окно показывает центрированный логотип и анимированное ожидание. `psutil` раз в 3 секунды проверяет только имя процесса `dota2`/`dota2.exe`. Это обнаружение процесса, не матча. Не обещать overlay поверх exclusive fullscreen. Никакого доступа к памяти/сетевому трафику игры.

При наличии системного трея закрытие главного окна оставляет приложение работающим в фоне; меню трея позволяет вернуть окно или завершить приложение. Если среда не предоставляет системный трей, окно закрывается обычно.

Порядок следующей работы:

1. Добавить реальные разрешённые метаданные/preview в страницу `Косметика`, сохранив явную маркировку образцов до появления источников.
2. Доработать окно ожидания и оверлей по результатам ручной проверки на KDE и Windows.
3. Проверить обнаружение процесса и работу системного трея на Windows; Linux логика и fake-based lifecycle тесты реализованы. Не читать состояние матча.
4. Подключить к вкладке статистики только публичные исторические карточки; live-матч и автоматический roster остаются `BLOCKED` до policy/source review.
5. Вкладка героя показывает локальные справочные данные/preview. Подмена официального тира, опыта или наград в клиенте не входит.
6. Отдельно оценить, существует ли разрешённый и совместимый локальный способ визуального применения косметики. Пока такой метод не подтверждён, показывать preview и работать с локальной подборкой; не писать в Dota install.
